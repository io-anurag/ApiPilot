# Implementation Plan: AI Failure Analysis (AP-031)

**Branch**: `030-ai-failure-analysis` | **Date**: 2026-09-23 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/030-ai-failure-analysis/spec.md`

## Summary

A user can ask the local AI to explain one failed request in an AP-026 uploaded-collection run.
Everything around the model's answer is deterministic:
- **Evidence** is extracted from the stored result, including the redacted raw capture on the
  local tier. When the request was generated by the session's current guided workflow, evidence
  also comes from specification context matched by exact Postman item id: the operation, scenario,
  documented responses, and upstream workflow steps with their outcomes in the same run.
- **The model** receives this numbered evidence through the existing `AIProvider`, together with
  a feature-owned system instruction. It answers with a versioned JSON object: a cause, a
  confidence, a summary, the evidence ids it relies on, and investigation steps.
- **Validation** turns low-confidence or uncited answers into an explicit "insufficient evidence"
  outcome, using a 0.5 threshold.
- **Storage**: the analysis is stored encrypted in a new AP-025 table, keyed by session, run and
  result position. It is replaced atomically on re-request and deleted with the session.
- **Concurrency**: one analysis runs at a time per session. A session-level in-progress route
  reports whether it is waiting for the local AI or generating, so the UI can disable other
  "Analyze" actions and show honest progress.
- **UI**: the result detail in `ExternalCollectionRunPanel` gains an "Analyze failure" action and
  a panel. The panel:
  - labels every explanation as an inference;
  - shows confidence as "Moderate" or "High" with the exact value;
  - lists cited evidence first, with the rest in a collapsed "Other evidence considered" section.

Three additive contract changes support this:
- `UploadedRequestResult.itemId`, the executed request's identity.
- `InferenceRequest.systemPrompt`.
- An optional `onStarted` hook on `AIProvider.infer`.

Decisions and alternatives are in [research.md](./research.md).

## Technical Context

**Language/Version**: TypeScript on Node.js 20 LTS (backend), React with TypeScript (frontend).

**Primary Dependencies**: The existing ones only: Express, `better-sqlite3` (AP-025),
`postman-collection` (read-only here), `@huggingface/transformers` behind `LocalProvider`, React,
Vite and Tailwind CSS v4. **No new dependencies.** Parsing and validation are hand-written, as in
the rest of the codebase.

**Storage**: One new SQLite table, `failure_analyses` (research D9), with an AES-256-GCM encrypted
payload via the existing `credentialCipher`.

**Testing**:
- Vitest, Supertest, React Testing Library and jsdom.
- Scripted `AIProvider` literals stand in for realistic model output.
- An in-memory database is used per test (`backend/tests/setup/testDb.ts`).
- An opt-in real-model evaluation runs under `AI_TEST_REAL_MODEL`.

**Target Platform**: A local web application (browser plus a Node backend on the same machine).

**Project Type**: A web application in an npm-workspaces monorepo: `backend/`, `frontend/`,
`packages/shared-domain/`.

**Performance Goals**:
- Once the model starts, one analysis resolves within `AI_INFERENCE_TIMEOUT_MS` (120 s default,
  SC-005). The projection is about 80 s at the default planning rates (research D8). Any earlier
  wait for the local AI is shown as its own phase (research D10).
- Evidence building, matching and validation add under 50 ms.

**Constraints**:
- Local or mock provider only, with no fallback (constitution V, XXIX).
- No request execution (FR-009).
- No secrets in the prompt, storage, logs or output (FR-011).
- Deterministic evidence, ids and request id.
- No automatic retry.
- One stored analysis per result.
- One analysis in progress per session.

**Scale/Scope**:
- One result per request. Runs are typically tens to a few hundred requests.
- Bodies are capped at 600 and 1,000 characters.
- At most 3 steps and a 400-character summary.
- Bulk analysis is out of scope.

`externalCollections/`, because the constitution (IX) names failure analysis as its own stage.

- recording `itemId` during AP-026 execution;
- the optional provider `systemPrompt`;
- the schema addition;
- the UI wiring.
