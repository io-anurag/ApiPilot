# Contract: Security Scenario Structure and Validation

**Status**: behavioural plus machine-readable. **Spec**: FR-017 to FR-024, FR-040. Machine-readable schema:
[security-scenario.v1.schema.json](security-scenario.v1.schema.json) (draft-07, validated with Ajv, the dependency already in the backend).
Field meanings are in [data-model.md](../data-model.md) §4.

## Validation pipeline

Every scenario version, whether generated by rule, suggested by AI or edited by a user, passes the same four steps before it
is stored. A failure rejects the whole version with every violation reported as a JSON Pointer; nothing partial is kept.

1. **Structure**: the draft-07 schema (closed vocabularies, required fields, bounds, `additionalProperties: false`).
2. **Domain**: the operation key exists in the current `ApiModel`; the category exists, is not `analysis-only`, and its
   taxonomy mapping matches the registry; every mutation target (`path`, `parameter`, `identity`) exists in the operation or
   the declared role set; `request.repeat.count` ≤ repeat ceiling; `plannedRequestCount` equals the sum implied by the
   mutations; `method.probe` is one of `HEAD`, `OPTIONS`, `TRACE`; every condition is allowed for the expected-behavior kind;
   documented status codes cited exist in the operation's `responses`.
3. **Safety**: no string field parses as an absolute URL, a scheme-relative URL or a host:port, outside documented example values;
   no header name is chosen by content; every probe and pattern id is in its fixed enumeration; destructive flag is true when
   the base operation is state-changing or when a create-with-no-cleanup applies (FR-045), and can be raised but never lowered
   by an edit; **no header, query, path or body value classifies as a credential** (`classifyValue`, `isSensitiveFieldName`
   with a non-placeholder value), because retained scenario rows survive the session (FR-051) and must never be a second secret
   store. Credential positions hold only the placeholder form the exporter already uses.
4. **Grounding**: `expected.basis` is `documented` only when `documentedStatusCodes` or a citation names a specification element;
   otherwise it must be `product-rule` with a `ruleId` from the fixed rule list in [evaluation-rules.md](evaluation-rules.md).

## Rejection reasons (stable codes)

`schema_violation`, `unknown_operation`, `unknown_field`, `unknown_identity`, `category_not_generatable`, `mutation_not_supported`,
`condition_not_allowed`, `url_in_content`, `header_override_not_allowed`, `repeat_over_ceiling`, `probe_not_in_set`,
`ungrounded_expectation`, `undocumented_status_cited`, `destructive_flag_lowered`, `credential_in_content`.

## Closed vocabularies

Mutations and conditions are exactly the unions in data-model §4.1 and §4.2. Adding a member is a contract change: a new
schema version note here, a code change in the registry of mutation builders and condition evaluators, tests for both, and
(if exportable) an exporter template or a documented limitation. There is no extension hook that accepts content from a
scenario.

## Stable identifiers and hashes

- Scenario id: `ss-` + 16 hex of SHA-256 over canonical JSON of `[operationKey, categoryId, mutation kinds in order, target, canonical mutation parameters]`.
- `contentHash`: SHA-256 over canonical JSON of the **material fields**: `operationKey`, `categoryId`, `baseRequest`, `mutations`,
  `expected`, `conditions`, `plannedRequestCount`, `destructive.flag`, `requiredIdentities`.
- Non-material fields (not in the hash): `title`, `objective`, `rationale`, `impact`, `suggestedSeverity`, `limitations`,
  `manualInputs`, `provenance` text. Editing only these keeps approval and records a new version.
- Canonical JSON: keys sorted, no insignificant whitespace, numbers as written by `JSON.stringify`.

## Determinism

`generateSecurityScenarios(apiModel, analysis, profileContext)` is a pure function. Identical inputs give identical scenarios, ids,
hashes and ordering (sorted by operation key, category id, scenario id). Time is injected and only appears in version
metadata, never in content or hashes.
